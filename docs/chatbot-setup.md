# 라온 웹사이트 안내봇

생성형 AI API를 호출하지 않는 JavaScript 규칙 기반 챗봇입니다. 라온은 프로젝트용으로 만든 고양이 SVG 아바타입니다. 별도의 공식 캐릭터 원본을 제공받은 이미지가 아니므로, 원본이 있으면 `assets/images/common/raon-chat-avatar.svg`를 교체하거나 flow JSON의 avatar 경로를 변경하면 됩니다.

## 적용 범위와 사용

`js/common.js`를 사용하는 모든 루트 포트폴리오 페이지에서 오른쪽 아래 버튼으로 실행됩니다. 별도 React 체험판과 카드뉴스 프로젝트에는 삽입하지 않습니다. 문의 페이지는 `contact.html`입니다. 기존 수달 마스코트는 버튼 위로 이동하고, 채팅창이 열리면 가려집니다.

메뉴: 포트폴리오 둘러보기 / 프로젝트 안내 / 자주 묻는 질문 / 제작·협업 문의.

`이전으로`는 직전 분기로 돌아가고, `처음으로`는 기록을 유지한 채 홈 메뉴로 돌아갑니다. `대화 초기화`는 이 챗봇의 sessionStorage 키와 현재 폼 입력을 삭제합니다. 다른 사이트 기능의 저장소는 삭제하지 않습니다. 개인정보가 포함될 수 있는 자유 질문 원문과 문의 폼 값은 저장하지 않습니다. 대화 복원은 등록된 질문 제목과 응답 식별자로 처리합니다. 탭을 닫으면 브라우저의 세션 수명에 따라 초기화되며, 파일 프로토콜의 브라우저별 저장소 격리 차이가 있습니다. 같은 HTTP(S) 출처에서 가장 일관되게 작동합니다.

## 답변 관리

- 원본: `assets/data/chatbot-flow.json`
- 문의 설정: `assets/data/inquiry-config.json`
- 수정 후: `node scripts/build-chatbot-data.mjs`
- 생성 파일: `js/chatbot-data.js` (수동 편집 금지)

로컬 `file://`에서도 JSON fetch 제한 없이 동작하도록 JSON을 검증 후 브라우저용 JS 데이터로 변환합니다. 런타임에 외부 AI 서비스나 CDN은 필요하지 않습니다. 키워드는 띄어쓰기·기호·대소문자를 정규화하고 정확히 등록한 키워드만 비교합니다. 더 구체적인 일치를 우선하며 동일한 점수의 여러 후보는 선택 버튼으로 제시합니다. 미등록 질문은 지정된 fallback 문구만 출력합니다.

## 먼저 확정해야 할 내용

1. 제작자 본인 소개, 공개할 전문 분야와 프로젝트별 실제 역할.
2. 최종 프로젝트 제목·기간·팀원·성과 (현재 페이지는 작성 중).
3. 콘텐츠·웹 제작 업무 범위, 비용 안내 방식, 실제 회신 예상 기간.
4. 자료 재사용·상업 이용 허가 조건.
5. 개인정보 처리 담당자·연락처, 보유 기간, 안내문 버전.
6. 실제 Supabase 프로젝트·기존 문의 테이블·필드와 RLS 정책.

미확정 내용은 임의로 작성하지 않았습니다. SNS 데이터는 대시보드 페이지로 안내하며 누적/기간 수치를 섞거나 실시간 값으로 단정하지 않습니다.

## 문의 연결 상태

저장소에서 기존 문의 HTML/테이블 연결은 확인되지 않았습니다. 연결된 프로젝트 `RouteMate - AI 여행 코스 추천`, `1234` 모두 INACTIVE 상태로 확인되어 임의로 복구하거나 새 프로젝트를 만들지 않았습니다. 현재 `enabled:false`로 개인정보 입력·전송을 비활성화하고, 접수 준비 중임을 안내합니다. 저장 성공으로 가장하지 않습니다.

문의 페이지와 챗봇은 `js/inquiry.js`의 같은 mount/submit 코드를 사용하고 같은 config.table에 저장합니다. source만 `contact_page` / `chatbot`으로 구분합니다.

연결 시 확인할 설정:

```json
{
  "enabled": true,
  "supabaseUrl": "https://실제프로젝트ID.supabase.co",
  "publishableKey": "sb_publishable_공개키",
  "table": "확인된문의테이블명",
  "privacyVersion": "확정한안내문버전",
  "retention": "실제로확정한보유기간",
  "privacyContact": "실제로확정한처리담당자연락처"
}
```

카테고리 설정은 기존 config의 categories를 유지합니다. 비밀키나 service_role 키를 사용하지 않습니다. 기존 테이블이 있을 경우 신규 테이블을 만들지 말고 실제 컬럼에 맞게 공용 제출 코드의 매핑을 수정합니다.

제출 데이터 계약: `id`(UUID, 재시도 중복 방지용 PK), `name`, `email`, `category`, `message`, `consent`, `privacy_version`, `source`. DB에서 `created_at`을 생성합니다. Supabase REST insert를 사용하고 `on_conflict=id`와 ignore-duplicates로 동일 요청 재시도의 중복 접수를 방지합니다. 전송 중 중복 클릭을 막고 실제 HTTP 성공 후에만 완료를 알립니다. 실패 시 폼 내용을 유지하며 오류 응답 원문이나 개인정보를 로그에 출력하지 않습니다.

실제 연결 전 반드시 익명 역할 INSERT만 허용하는 RLS, 동의·길이·유형 검증을 DB에서 확인합니다. 익명 SELECT/UPDATE/DELETE는 허용하지 않습니다. 관리자 조회는 Supabase Dashboard/Table Editor에서 수행하며, 공개 문의 목록은 만들지 않습니다. 별도 관리자 웹페이지가 필요하면 관리자 Auth와 권한 정책을 추가해야 합니다. 공개 배포 시 서버 측 요청 제한이나 스팸 방지도 별도로 검토해야 합니다.

연결 완료 검증은 테스트 문의 동의 누락 차단, 실제 저장, 두 source 값, 익명 조회 거부, 실패/재시도 중복 방지 순서로 진행합니다. 현재 원격 DB 저장은 미검증 상태입니다.

## 검증

`node --test tests/chatbot.test.cjs`로 실제 분기 JSON의 대상, 키워드 분류, 미등록 입력, 손상된 세션과 개인정보 미복원 동작을 확인합니다. 브라우저 검증은 열기/닫기, 분기 이동, 새로고침 복원, 페이지 간 복원, 초기화, 동의 및 실제 전송 성공/실패를 포함합니다. 생성 데이터 파일과 함께 커밋해야 합니다.
